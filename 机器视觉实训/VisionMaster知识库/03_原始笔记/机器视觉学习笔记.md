## 1. 这两个软件是什么（一句话定位）

都是**海康机器人（Hikrobot）** 的机器视觉产品，一条完整的产业链，分上下两层：

| 软件 | 角色 | 干什么 |
|------|------|--------|
| **MVS** | 底层 · 相机 SDK | 负责**采图**：把工业相机的画面变成电脑能算的"数字"。**写代码**使用 |
| **VisionMaster** | 上层 · 视觉平台 | 负责**判断**：对着图像问"合格吗？尺寸对吗？"。**拖积木**使用，不用写代码 |

> **关系一句话**：VisionMaster 用 MVS 去拿图，然后处理。MVS 是"端茶倒水的"，VisionMaster 是"做判断的"。

## 2. 采图的五步主线（万能骨架）

> **这是 MVS 所有代码共有的固定顺序**，换 Python / C++ / C# 都一样。记住这五步，其余全是参数微调。

```
① 枚举设备    —— 找到相机（哪台设备在线上）
② 打开设备    —— 建立连接（独占/共享模式）
③ 开始取流    —— 开始持续送图像（StartGrabbing）
④ 拿一帧图像  —— 从缓冲里取出一张画面（GetImageBuffer）
⑤ 停止取流 + 关闭 + 销毁句柄
```

参考真实代码：`<MVS安装目录>\Development\Samples\Python\General\GrabImage\GrabImage.py`

MVS 自带 **13 种语言** 的例程（在 `Development\Samples\` 下）：C# / C++ / Python / Java / VB / Delphi / Cuda / OpenCV / Halcon / LabVIEW / VisionPro / MvSerial。

## 3. VisionMaster 的"积木"都有哪些

> VisionMaster 帮助文档里出现频率最高的算子关键词（从 `Help\CH\` 统计得出）：

标定(1536) · 测量(1031) · 定位(796) · 缺陷(1391) · 图像(5552) · 阈值(457) · 滤波(319) · 模板匹配(155) · 深度学习(265) · 字符识别/OCR · 形态学 · 找边 · 找圆

这些都是**"判断"的积木**，含义对口对照：

| 积木 | 干什么 | 比喻 |
|------|--------|------|
| **模板匹配** | 拿一张标准样张，在画面里"找与它一模一样的东西" | 人脸识别找同款 |
| **测量 / 找边 / 找圆** | 量尺寸，判断合格与否 | 量身高 |
| **缺陷检测** | 找瑕疵（划痕、脏点、缺角） | 质检员挑次品 |
| **字符识别(OCR)** | 认字（喷码、日期、序列号） | 读标签 |
| **标定** | 把"像素"换算成"真实毫米数" | 给尺子对刻度 |

## 4. 视觉检测的通用骨架（最重要的思维模型）

> **几乎所有机器视觉项目都是这个套路**，换检测电子元件、螺丝、包装全绕不开。

```
拍照 → 找到东西在哪 → 只看要查的那块区域 → 判断有没有问题
```

## 5. 实操案例：玻璃板划痕检测（流程怎么搭）

**我的错误版本（第一次构思）：** 模板匹配 → 定位 → 缺陷检测 → 定位 → 标定

**存在的 4 个坑：**
1. **漏了第一步"采集"** —— 任何流程第一块积木永远是拍照/取图。
2. **模板匹配和定位是同一件事** —— "模板匹配"模块找到样板后**同时给出位置**，不用再单独加"定位"。
3. **漏了"检测区域 ROI"** —— 找到玻璃后**不能整张图都测**，要只框出该查的那块。边缘、台面反光都会误判。**这是新人最大的坑。**
4. **标定放错位置** —— 标定是"像素→毫米"的换算，是**前期一次性设置**；而且**只判断"有无划痕"根本不需要标定**（要报真实尺寸才需要）。

**✅ 正确版本（有无划痕检测）：**

```
采集 → 模板匹配(找到玻璃+定位) → 定义检测区域ROI → 缺陷检测(找划痕) → 输出结果(有/无)
```

> 需要报"划痕长 xx mm"时，才额外把"标定"作为前置步骤加上。
