# 官方例程解读（CalibGuideSample + ApplicationTemplate）

> **来源**：`VisionMaster4.3.0\Applications\` 下的 CalibGuideSample（标定引导示例）与 ApplicationTemplate（方案模板）。
> **用途**：官方提供的**可直接打开运行的示例方案**，是学习"整套流程怎么搭"的最佳教材。
> **本章特色**：用 `.prc` 文件（本质是 ZIP 容器）解析出每个方案的**模块流程结构**，让你直接看懂官方方案内部是怎么连线的。

---

## 1. 例程在哪儿

```
<VisionMaster安装目录>\Applications\
├── CalibGuideSample\           ← 标定引导示例（6个方案）
│   ├── static.prc             静态标定 + 中文版
│   ├── static_en.prc          静态标定 + 英文版
│   ├── dynamic.prc            动态标定 + 中文版
│   ├── dynamic_en.prc         动态标定 + 英文版
│   ├── reflect.prc            映射标定 + 中文版
│   └── reflect_en.prc         映射标定 + 英文版
└── ApplicationTemplate\        ← 方案模板（启动引导的"方案类型"）
    ├── Detection\   (测量)
    ├── location\    (定位)
    └── Multi\       (多任务)
```

> 中英文版本只是界面语言不同，**流程逻辑完全一致**。下面解析的是中文版流程。

---

## 2. .prc 文件本质：ZIP 包

`.prc`（方案文件）其实是一个 **ZIP 压缩包**，解压后能看到：

```
ProcFile\UiParamData\_0+0+ImageSourceModule    ← 每个模块的参数
ProcFile\ProcedureInfo.xml                      ← 流程定义（模块+连接关系）
ProcFile\ProcedureMoudleFrame                   ← 界面布局
```

**`ProcedureInfo.xml` 是关键**，里面写清了：流程名、每个模块的索引/名称/显示名、模块之间的前后连接关系（`FrontModules`/`FollowingModules`）、以及数据订阅关系（`ModuleSubscribe`）。

> 这就是为什么能"看懂官方方案的内部结构"——XML 把流程图画出来了。

## 3. 三个标定示例的流程结构（逐模块解析）

### 3.1 static.prc —— 静态标定

**流程名**：静态标定　｜**模块链**：

```
[0] 图像源1  →  [1] 标定板标定1  →  [2] 协议组装1  →  [3] 发送数据1
```

| 模块 | 作用 | 备注 |
|------|------|------|
| 图像源1 | 提供标定板图像 | 流程起点 |
| 标定板标定1 | 用标定板算出像素精度等 | **核心**（对应第6章） |
| 协议组装1 | 把标定结果组装成协议数据 | 数据内务 |
| 发送数据1 | 把结果发给外部（PLC等） | 输出 |

> **数据订阅**：标定板标定订阅了图像源的图像/宽度/高度/像素格式；协议组装订阅标定结果；发送数据订阅协议组装状态。
> **一句话**：拍标定板 → 算出标定参数 → 打包 → 发出去。这是"静态标定"的标准四步。

### 3.2 dynamic.prc —— 动态标定（N图像标定）

**流程名**：动态标定　｜**模块链**：

```
[0] 图像源1 → [2] N图像标定1 → [3] 协议组装1 → [4] 发送数据1
（另有 [1] 协议解析1、[5] 分支模块1、[6][7] 发送数据2/3 参与流程控制）
```

| 模块 | 作用 | 备注 |
|------|------|------|
| 图像源1 | 提供图像 | |
| N图像标定1 | **用多张图（机械手多位置）标定** | **核心**（配合运动机构） |
| 协议解析1 | 解析外部来的控制指令 | 触发动态标定 |
| 分支模块1 | 按条件走不同分支 | 流程控制 |
| 发送数据1/2/3 | 多路输出结果 | |

> 动态标定比静态复杂**因为多了"通信触发 + 分支"**：先收到外部指令（协议解析），再决定走哪条分支去标定（N图像标定），最后多路发送。适合"机械手边动边拍、多位置标定"的场景。

### 3.3 reflect.prc —— 映射标定

**流程名**：映射标定　｜**模块链**：

```
[1] 分支字符1 → [2] 图像源1 ┐
                  [3] 图像源2 ┼→ [4] 映射标定1 → [5] 协议组装1 → [6] 发送数据1
（[0] 协议解析1 触发）
```

| 模块 | 作用 | 备注 |
|------|------|------|
| 协议解析1 | 解析外部指令 | 触发 |
| 分支字符1 | 按字符分支 | 控制 |
| 图像源1 / 2 | 两路图像 | **双相机/两幅图** |
| 映射标定1 | 建立两幅图坐标映射 | **核心**（多相机） |
| 协议组装1 / 发送数据1 | 打包输出 | |

> 映射标定**用了两个图像源**（两个相机或两幅图），把两路图像的坐标**映射**到同一坐标系。适合多相机协同、大图拼接等场景。

## 4. 三个示例对比（帮你选）

| 示例 | 核心模块 | 适用场景 | 复杂度 |
|------|---------|---------|--------|
| **static 静态标定** | 标定板标定 | 固定相机、纯图像测量（求像素精度） | ⭐ 简单 |
| **dynamic 动态标定** | N图像标定 | 机械手移动多位置标定（手眼标定） | ⭐⭐ 中 |
| **reflect 映射标定** | 映射标定 | 双/多相机坐标映射 | ⭐⭐ 中 |

> **新手建议**：先跑 **static.prc**（最简单、只用了4个模块），把它当"标定入门"。理解"图像源→标定→组装→发送"这条最小闭环，再看 dynamic/reflect 更复杂的流程。

## 5. 方案模板（ApplicationTemplate）

这是启动引导界面里,选方案类型（通用方案/定位测量/缺陷检测/用于识别）时提供的**预设流程模板**：

```
ApplicationTemplate\
├── Detection\  → 分类名 Measurement（测量）
│   ├── General\GeometryDetection\  通用-几何检测
│   └── Profession\GeometryDetection\  专业-几何检测
├── location\   → 分类名 定位
│   ├── General\GeometryDetection\
│   └── Profession\GeometryDetection\
└── Multi\      → multitask_App（多任务）
```

- 每级目录有个 `ApplicationItemInfo.xml`，记录分类名（`<name>`）和优先级（`<priority>`）。
- **分类逻辑**：按**行业/复杂程度**分了"通用 General"和"专业 Profession"，再往下按**功能**（几何检测等）细分。
- **作用**：你新建方案时，从这些模板里挑一个，VisionMaster 会**预置一条初始流程**，你再改，比全部从零拖要快。

## 6. 动手任务（学习者）

1. 在 CalibGuideSample 里，**用 VisionMaster 打开 `static.prc`**，看它的 4 个模块和流程图。
2. 试着把"标定板标定"模块的结果（像素精度、标定误差）打印/查看出来。
3. 对比打开 `dynamic.prc` 和 `reflect.prc`，观察模块数量和流程复杂度差异。
4. 新建方案时，选"定位测量/通用方案"，观察 VisionMaster 是否预置了一条流程（来自 ApplicationTemplate）。
5. 把 static.prc 的流程改成"图像源→模板匹配→检测"，理解"官方示例"和"你自己的项目"的距离在哪。

> 目标：**看懂官方方案 = 学会"用模块搭最小闭环"**。你以后设计的任何流程，本质上都是"采集→(定位)→(检测/测量)→(标定)→输出"的变体。
