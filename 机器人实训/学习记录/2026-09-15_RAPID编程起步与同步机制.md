# 2026-09-15 · RAPID 编程起步：模块结构与"两层存储 + 同步"机制

> **来源**：实操（RobotStudio 6.08 虚拟控制器 `260913System1`）+ 官方手册《RAPID 语言内核技术参考手册》（**字符集**、**模块声明**、**过程声明**）、《RobotStudio 操作员手册》（**同步** / 同步到工作站 / 同步到 RAPID）。
> **本日定位**：机器人实训**第 3 天**，开始学 RAPID 编程。这天先撞上了两个"环境级"的坑（**`main` 缺失**、**同步方向**），把它们搞清楚才算真正迈进编程的门。

## 一、程序入口 `main`：每个任务必须有且仅有一个

### 1. 报错
```
'T_ROB1'中的RAPID符号'main'未找到。
260913System1/RAPID/T_ROB1
```

### 2. 原因
RAPID 规定：**程序从 `main` 开始执行**。任务 `T_ROB1` 里所有模块的例行程序加起来，**必须恰好有一个 `main`**——没有它就"找不到入口"，无法启动。

我查过：当时 `Module1` 里只有 `demo1` / `Path_10` / `Path_20`，**全任务都没有 `main`**，所以报这个错。

### 3. 解决
在**模块内部**加一个 `main`，把要跑的子程序放进去：

```rapid
	PROC main()
		Path_20;        ! 想跑哪条就写哪条
	ENDPROC
```

> **类比**：`main` 相当于 C 语言的 `main()`。子程序再多，没有入口也启动不了。
> **注意**：全任务**只能有一个** `main`，模块多了容易撞名。

## 二、★ 模块结构：`PROC` 不能写在 `MODULE` 外面

### 1. 报错（一次报 3 条，其实是同一个原因）
```
<mod2>(1,1): 语法错误(135): 预期值 'module'
<mod2>(4,5): 语法错误(137): 预期值为 'trap' ，但找到的是 'module'
<mod2>(23,2): 语法错误(135): 预期值 'endtrap'
未找到符号：/RAPID/T_ROB1/<mod2>
启动: 语法错误，不允许操作。
```

### 2. 原因：把 `main` 粘到了 `MODULE` 之前
出错的写法（错误示范）：

```rapid
PROC main()              ← ❌ 模块外面不能直接写 PROC
    Path_20;
ENDPROC
    MODULE Module1       ← 文件应该从这里开始
	...
ENDMODULE
```

解析器读第 1 行的 `PROC`，以为要写模块级的 **`TRAP` 陷阱例行程序**，于是往下找 `ENDTRAP`，结果第 4 行撞见 `MODULE` 就全乱了——三种报错**是同一处错误的连锁误判**。

### 3. 正确结构（手册《语法概述》的模声明）

```
<module declaration> ::= MODULE <module name> <type definition list>
                         <data declaration list> <routine declaration list> ENDMODULE
```

也就是——**所有数据声明和例行程序都必须在 `MODULE` 与 `ENDMODULE` 之间**：

```rapid
MODULE Module1                    ← 文件必须以 MODULE 开头
	CONST robtarget p10:=...       ← 数据声明
	PROC main()                    ← 例行程序（含 main）都在内部
		Path_20;
	ENDPROC
	PROC demo1() ... ENDPROC
ENDMODULE                         ← 模块在这里结束
```

> **口诀**：**`MODULE` 开头、`ENDMODULE` 收尾，`main`/`demo1`/各 `PROC` 全部夹在中间。**

## 三、★★ 为什么"示教器"和"软件"数据不互通

这是本日第二大收获，也是 RobotStudio **最容易踩的坑**。

### 1. 一份程序，两个存储位置

| | 软件侧（站点） | 示教器侧（控制器） |
|---|---|---|
| 存哪 | `Stations\260913Study1.rsstn` | `Systems\260913System1\INTERNAL\RAPID\PRG1\` |
| 格式 | **结构化对象图**（XML，程序被拆成 `ProcedureDeclaration`/`RoutineCalls` 等互引对象） | **纯文本 RAPID** |
| 面向 | 离线编程（路径、目标点等图形对象） | 真机/仿真运行 |

**它们各存各的，不会自动跟随**。手册《同步》开篇就说：

> **"同步即确保在虚拟控制器上运行的系统的 RAPID 程序与 RobotStudio 内的程序相符。"**

注意是"**确保相符**"——**默认它们可以不相符**，要手动同步去对齐。

### 2. 两个方向，方向反了就是"覆盖"

| 按钮 | 方向 | 谁覆盖谁 | 手册说何时用 |
|---|---|---|---|
| **同步到 RAPID** | 工作站 → 控制器 | **软件赢** | 用"工作站内的最新更改"更新控制器（仿真前、存盘前） |
| **同步到工作站** | 控制器 → 工作站 | **控制器赢** | **"对程序进行了基于文本的编辑"之后** |

**本日实际踩的坑**：在**示教器**里写了代码（只在控制器里），却点了 **`同步到 RAPID`**（软件 → 控制器）→ **软件里的旧版把控制器里的新版顶掉了**。

> 这不是"数据不互通"，而是**同步方向选反，拿旧版覆盖了新版**。

### 3. 正确用法（三条）

| 你改的是 | 该点 |
|---|---|
| **示教器 / RAPID 编辑器里敲的代码** | **`同步到工作站`**（控制器 → 软件） |
| **软件里画路径 / 改目标点** | **`同步到 RAPID`**（软件 → 控制器） |

- **同步前先确认哪边是最新的**，别把好的覆盖掉；
- **拿不准时先存一份再同步**。

## 五、要点串记

- **`main` 是入口**：每任务有且仅有一个；缺了就报"未找到符号 main"。
- **结构铁律**：`PROC` 必须在 `MODULE`…`ENDMODULE` **内部**；写在外面会连报 3 条"预期值 module/trap/endtrap"。
- **两层存储**：站点（`.rsstn`，对象图）↔ 控制器（`PRG1\`，纯文本），**各存各的**。
- **两个同步方向别反**：改**代码**→`同步到工作站`；改**图形对象**→`同步到 RAPID`。**反了就是旧版覆盖新版**。
- **同名模块别并存**，否则撞名报错。
