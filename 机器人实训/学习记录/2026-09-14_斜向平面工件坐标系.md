# 2026-09-14 · 斜向平面上的工件坐标系建立（范围须为"全局" + 注意 Z 轴方向）

> **来源**：实操（**真机机械台**，示教器 FlexPendant）+ 官方手册《带 FlexPendant 的 IRC5 操作员手册》（新建 / 编辑数据实例、创建工件）、《RobotStudio 操作员手册》（方向、三点法创建框架）。
> **本日成果**：在**随机斜向平面**（白色包装盒的倾斜顶面）上建立工件坐标系 `wobj1`，并在其上示教/加工。
> **两条要领**：
> ① **编辑里要把范围改成「全局」**，之后切换工件坐标**才能生效**；
> ② **注意 Z 轴方向**，方向选错会**顶到工件/夹具 → 卡机器**。

## 一、今天做的事：工件坐标系建在"斜向平面"上

工件是白色包装盒（"智慧家庭助理"），机器人要在它**倾斜的顶面**上作业。这个面**既不水平、也不与大地/机器人的轴对齐**（所谓"随机斜向"），所以**不能靠手输坐标**，只能**在斜面上实测取点**，让控制器算出这个面的坐标系。

![斜向平面工件（盒顶斜面）与机器人](../../配图/Day3_images/image-0914_incline_wobj_realmachine.jpg)

**为什么斜面更要建工件坐标系**：建好之后，工具沿这个坐标系的 **Z 轴（斜面法线方向）** 接近工件，就相当于"垂直于工件表面"进退刀——比在大地坐标系里同时摆动 X、Z 两个方向精确、省力。（手册原文："如果工具坐标系的其中一个坐标与钻孔平行，则能轻而易举地使用机械爪将销子定位于钻孔内。在基坐标系中执行同样的任务时，可能需要同时在 x 和 z 坐标进行微动控制，从而增加了精确控制的难度。"）

## 二、★★ 要领一：范围选「全局」，切换才生效

### 1. 现象（实操发现）
建立 `wobj1` 后，在**手动操纵 - 工件**列表里能看到它，但**切换（激活）却不生效**。原因：**它的"范围"是"任务"**。把范围改成**「全局」**后，切换正常生效。

### 2. 截图实证
`手动操纵 - 工件` 对话框，**当前选择 `wobj1`**；列表里两个工件：

| 工件名称 | 模块 | 范围 |
|---|---|---|
| `wobj0` | `RAPID/T_ROB1/BASE` | **全局** |
| `wobj1` | `RAPID/T_ROB1/Module1` | **任务** ← 就是它不生效 |

右键/`编辑` 菜单里有「**更改值… / 更改声明… / 复制 / 删除 / 定义…**」——**改"范围"走的就是「更改声明」**。

![手动操纵-工件：wobj1 范围是"任务"（编辑→更改声明可改）](../../配图/Day3_images/image-0914_wobj1_scope_menu.png)

### 3. 手册依据（"范围"的三个选项）
`05_带FlexPendant…\doc95`（新建数据实例）明确给出**范围**的三档含义：

| 范围 | 含义（手册原文） |
|---|---|
| **全局** | **所有任务都可以使用** |
| 本地 | 仅模块内部可以使用 |
| 任务 | 仅任务内部可以使用 |

而 `doc106`（创建工件）直接写：**"所有模块中，工件都应该是程序中的全局变量"**；`doc99`（创建工具）也写"**工具应该始终保持全局状态**，以便用于程序中的所有模块"。

> 也就是说：**手册本来就要求工件/工具用"全局"**，本次实操踩的坑正是**建成了"任务"导致切换不生效**——**改"范围"的入口是：选中工件 → `编辑` → 「**更改声明**」**（`doc96`：编辑数据实例可改 `名称 / 范围 / 存储类型 / 模块 / 例行程序`）。

### 4. 顺带提醒（存储类型）
同一次"更改声明"里还有**存储类型**：`持续（Persistent）/ 变量（Variable）/ 常量（Constant）`。手册要求**工件/工具应为持续变量**，否则 **RAPID 复位后标定值会丢**。（此项与今日另一篇《工具与工件坐标系新建》里"待核对"的一条呼应，见第五节。）

## 三、★★ 要领二：Z 轴方向要避免"卡机器"

### 1. 为什么会卡
工件坐标系的 **Z 轴 = 工件表面的法线方向**。而机器人**进/退刀大多沿工具或被选坐标系的 Z 轴方向**走：
- **Z 轴指向"工件内部 / 朝下"**：工具会**往材料里顶**，轻则撞到夹具，重则**卡死、报警、停机**；
- **Z 轴指向"工件外侧 / 朝上"**：工具才能**先退开再接近**，动作顺畅。

所以斜面取点时，**要特意让算出的 Z 轴朝外**，别让它扎进工件。

### 2. 手册依据（Z 轴与表面垂直）
`01_RobotStudio…\doc53`（方向）：**"目标 Z 轴的方向是如何与表面垂直的"**——即**目标/框架的 Z 轴应与表面垂直（沿法线）**；把方向设为"垂直于表面"，就是让 Z 轴对准该面的法线（也可用"表面上的特定点作为法线参照物"）。

> 实操口诀：**在斜面上取三点定框架后，务必检查 Z 轴（法线）朝向——朝外，别朝里。**

## 四、斜面上建立工件坐标系的操作纲要（3 点法）

在斜面上用**三点法**定平面（与平地面上的做法一致，只是点落在斜面上）：

1. **新建** `wobjdata` 数据实例（本次 `wobj1`）；
2. **改声明**：**范围 = 全局**（★ 要领一）、存储类型 = 持续；
3. **定义**：`编辑 → 定义…`，用户方法选 **3 点**，依次取
   - **用户点 X1**（靠近原点）
   - **用户点 X2**（沿 X 正方向较远，**X1–X2 越远越准**）
   - **用户点 Y1**（在 Y 方向上，与 X 轴垂直）
   → X 轴过 X1–X2、Y 轴过 Y1，**两条相交垂线的交点即原点**，Z 轴由平面法线定出；
4. **检查 Z 轴朝向**（★ 要领二），确定后保存；
5. 定义时**确认"活动工具"正确**（此前笔记已记：手册要求"确保激活了正确的工具和工件"）。

## 六、要点串记

- **斜向平面也得靠"斜面上取点"建坐标系**，不能手输；三点法：X1、X2 定 X 轴，Y1 定 Y 轴，交点即原点。
- **★ 范围必须选「全局」**，否则切换工件坐标**不生效**；**改的入口是 `编辑 → 更改声明`**（`wobj0` 天生全局、不可重新定义）。
- **★ Z 轴方向要朝外**（沿表面法线），**别朝里/朝下**，否则进退刀会**顶进材料、卡机器**。
- **存储类型用"持续"**，避免 RAPID 复位后标定值丢失。
- **定义时确认"活动工具"**，工具选错 → 取点全偏。
