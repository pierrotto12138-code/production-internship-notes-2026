# 2026-09-15 · 画圆拓展（两组圆）与编程易错点排查

> **来源**：实操（RobotStudio 6.08 虚拟控制器 `260913System1`）+ 运行时排错。
> **本日成果**：把"画三个圆"**扩展到两组基准点**（`Target_160` / `Target_260`），并在此过程中**踩中并排掉 5 个典型坑**——其中"**带参数的例程不能作为程序入口**"是一条硬规则。
> **一句话**：**先跑通，再谈优雅**——两份独立的无参例程虽然重复，但**能直接设 PP、不易出错**，是当前可行的方案。

## 一、最终方案：两组圆，两份独立例程

```rapid
    PROC draw_circles()                 ! 第 1 组：Target_160（z=473 平面）
        VAR num i;
        FOR i FROM 0 TO 2 DO
            MoveJ Offs(Target_160,i*40,0,0),v50,z0,MyTool\WObj:=wobj0;
            MoveC Offs(Target_160,i*40+20,-20,0),Offs(Target_160,i*40,-40,0),v50,z0,MyTool\WObj:=wobj0;
            MoveC Offs(Target_160,i*40-20,-20,0),Offs(Target_160,i*40,0,0),v50,z0,MyTool\WObj:=wobj0;
        ENDFOR
    ENDPROC

    PROC draw_circles_260()             ! 第 2 组：Target_260（z=408 平面）
        VAR num i;
        FOR i FROM 0 TO 2 DO
            MoveJ Offs(Target_260,i*40,0,0),v50,z0,MyTool\WObj:=wobj0;
            MoveC Offs(Target_260,i*40+20,-20,0),Offs(Target_260,i*40,-40,0),v50,z0,MyTool\WObj:=wobj0;
            MoveC Offs(Target_260,i*40-20,-20,0),Offs(Target_260,i*40,0,0),v50,z0,MyTool\WObj:=wobj0;
        ENDFOR
    ENDPROC
```

**两组圆的位置差异**（`Offs` 偏移量相同，仅基准点不同）：

| 组 | 基准点 | 坐标 | 所在平面 |
|----|--------|------|---------|
| 1 | `Target_160` | (752.961, 0, 473) | z = **473** |
| 2 | `Target_260` | (858.409, 63.326, 408) | z = **408** |

> 两组**形状完全一样**（半径 20、圆心间距 40 相切），只是**位置不同**——因为 `Offs` 的偏移量是沿**工件坐标系**方向（`wobj0`），**与基准点的姿态无关**。

## 二、★★ 本次踩中的 5 个坑（排错经验）

### 坑 1：复制代码时漏掉 FOR 头 → "未声明的标识符"

```rapid
    PROC draw_circles_260()
        MoveJ Offs(Target_260,i*40,0,0),...     ← ❌ i 未声明；也没有 FOR
        MoveC Offs(Target_260,i*40+20,-20,0),...
    ENDPROC
```

**原因**：从 FOR 版复制时，**只抄了循环体，漏了 `FOR...ENDFOR` 头尾**；计数器 `i` 由 `FOR` 自动声明（手册），没有 FOR 头自然就"未声明"。
**报错**：程序检查报"RAPID 程序中存在错误 / 40160"。
**教训**：**抄循环体必须连 `FOR…ENDFOR` 一起抄**；`VAR num i;` 可写可不写（本例写了，但不是必须）。

### 坑 2：基准点混用 → 形状错误

```rapid
        MoveJ Offs(Target_260, i*40, 0, 0), ...      ← 起点用 260
        MoveC Offs(Target_260, ...), Offs(Target_160, ...), ...   ← ❌ 终点用 160
```

**后果**：两个基准点相距 **105mm(X) / 63mm(Y) / 65mm(Z)**，**画出来不是圆**，而且 z 从 408 跨到 473，TCP 会跑到别的平面去。
**教训**：**同一个程序里，基准点必须全用同一个**。160 版全用 `Target_160`，260 版全用 `Target_260`。

### 坑 3 ★：带参数的例程**不能作为程序入口（PP）**

**报错原文**（RobotStudio .NET exception）：
```
C004900F : Given routine is not a legal entry point.
Possible reasons are: routine is a function, or routine has parameters.
```

**含义**：**把程序指针（PP）设到 `draw_circles` 失败**，因为它是 `PROC draw_circles(robtarget base)`——**带参数的过程不是合法入口**。

**硬规则**：
> **程序指针（PP）只能指向"无参数的过程"。**
> 带参数的例程、函数（`FUNC`）**都只能被调用，不能当起点**。

**正确用法**：**PP 设到 `main`，由 `main` 调用带参数的例程**：
```rapid
    PROC main()
        draw_circles(Target_160);       ← 由 main 调用
    ENDPROC
```

> 这一条是**本次最重要的收获**——以后写"带参数的动作程序"，一律**从 `main` 调它**，不要直接设 PP。

### 坑 4：改了"签名"却没改"函数体" → 静默错误

```rapid
    PROC draw_circles(robtarget base)      ← 签名声明了 base
        VAR num i;
        FOR i FROM 0 TO 2 DO
            MoveJ Offs(Target_160,i*40,0,0),...     ← ❌ 函数体还是 Target_160
        ENDFOR
    ENDPROC
```

**问题**：**只把 `()` 改成 `(robtarget base)`，却忘了把函数体里的 `Target_160` 改成 `base`**。
**危险性**：**不报错**（`base` 只是没被使用，语法合法），但**调用 `draw_circles(Target_260)` 仍会画在 Target_160 的位置**——**静默错误最难查**。
**教训**：**改参数要"签名 + 函数体一起改"**，改完搜一遍新参数名是否真的被用上。

### 坑 5：视图面板被关掉 → 无法操作

**现象**：左侧"布局 / 路径和目标点"浏览器不见了，界面只剩 3D 视图，感觉"啥也干不了"。
**恢复**（手册《窗口布局》）：
> **"您可以从 自定义快速访问 ⯆ > 窗口布局 > 窗口 来访问'窗口'菜单。"**
> **"默认布局：设置窗口布局为默认设置。"**

**操作**：标题栏左侧的**自定义快速访问工具栏 ⯆ → 窗口布局 → 默认布局**（或 → 窗口 → 勾选"布局"）。
**另**：面板只是**被隐藏**，**数据不会丢**——切回"基本"选项卡通常也会带回来。

## 三、方案权衡：两份独立 vs 一份带参数

| | **两份独立无参 PROC**（当前采用） | 一份带参数 PROC |
|---|---|---|
| 设 PP | ✅ **可直接设** | ❌ 不能设，必须从 `main` 调 |
| 代码重复 | ⚠️ 重复两份 | ✅ 只写一份 |
| 出错风险 | 复制时易漏改（本次就栽了） | 改签名/函数体要同步 |
| 适用 | 调试阶段、要快速验证 | 例程多、要复用 |

**结论**：**当前用两份独立无参例程是对的**——简单直接、可任意设 PP。等例程多了再考虑参数化，且**必须记住从 `main` 调用**。

## 四、要点串记

- **两组圆 = 两个无参例程**，基准点分别是 `Target_160`（z=473）/ `Target_260`（z=408）。
- **抄循环体必须连 `FOR…ENDFOR` 头尾一起抄**（计数器由 `FOR` 自动声明，`VAR` 可写可不写）。
- **一个程序里基准点必须统一**，混用会画错形状。
- **★ 带参数的例程 / 函数不能设 PP**（`C004900F`）——**从 `main` 调用**。
- **改参数要签名与函数体同步**，否则出现"不报错的错"。
- **视图丢了用「窗口布局 → 默认布局」找回**，数据不丢。
- **`Offs` 偏移沿工件坐标系**，与基准点姿态无关。
